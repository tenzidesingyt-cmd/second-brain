# Второй мозг

Личный кабинет для мыслей, задач и медиа. Вход с компьютера и телефона: инбокс, AI-разбор, заметки, задачи, привычки, календарь и аналитика. Кабинеты пользователей изолированы: каждый видит только свои записи.

## Возможности

- **Инбокс** — текст, фото, видео, голосовые и файлы. Материал сохраняется сразу, разбор ИИ запускается отдельно.
- **AI-разбор через OpenRouter** — распознаёт текст на фото, расшифровывает голос, раскладывает материал на заметку, задачи и события, подставляет сроки.
- **Заметки** — Markdown, вложения, теги, типы, полнотекстовый поиск и AI-поиск по смыслу.
- **Задачи и привычки** — приоритеты, сроки, отметки выполнения, серии.
- **Календарь** — события и задачи на месяц, быстрый переход к дню.
- **Аналитика** — недельная сводка и AI-итоги.
- **Realtime** — изменения мгновенно появляются на всех устройствах через WebSocket.
- **PWA** — установка на телефон и компьютер, офлайн-оболочка, быстрый захват с домашнего экрана.
- **Регистрация через Telegram-бота** — человек пишет боту `/start`, получает логин и пароль и входит на сайте. Пароль можно сбросить командой `/password`.
- **Напоминания** — push в браузере и сообщения в Telegram о задачах и событиях: за день в 09:00 и в момент времени, с учётом часового пояса.
- **Несколько пользователей** — у каждого свой кабинет: заметки, задачи, события, привычки, инбокс и файлы не пересекаются. Владелец видит список аккаунтов и управляет ИИ.
- **Вход через Google** — OAuth 2.0 для аккаунта владельца. Резервный пароль задаётся в `APP_PASSWORD`.
- **Экспорт данных** — заметки, задачи, события и привычки одним JSON-файлом.

## Стек

React 19, TypeScript, Vite, TanStack Query, Express 5, SQLite (`node:sqlite`, FTS5), WebSocket (`ws`), OpenRouter, PWA.

## Быстрый старт

Нужен Node.js 24 или новее — приложение использует встроенный `node:sqlite`.

```bash
npm ci
cp .env.example .env
npm run build
npm start
```

Приложение откроется на `http://localhost:8787`.

Если не заданы `APP_PASSWORD`, Google OAuth и токен Telegram-бота, приложение открывается без входа — так удобно только в домашней сети. Для доступа из интернета обязательно настройте хотя бы один способ входа.

Для разработки с горячей перезагрузкой:

```bash
npm run dev
```

Vite поднимется на `http://localhost:5173` и будет проксировать API на `http://localhost:8787`.

### Настройка ИИ

1. Получите ключ на [openrouter.ai/keys](https://openrouter.ai/keys).
2. Укажите `OPENROUTER_API_KEY` в `.env` или вставьте ключ на экране **Настройки**.
3. Проверьте связь кнопкой «Проверить подключение».

Ключ из `.env` имеет приоритет над ключом из настроек. Модели по умолчанию: `google/gemini-2.5-flash` для текста и фото, `openai/whisper-1` для голоса. Их можно заменить в настройках.

### Вход через Google

Google-вход остаётся запасным способом для владельца кабинета: он привязывает вход к одному Gmail, остальные Google-аккаунты получают отказ. Остальные пользователи регистрируются через Telegram-бота.

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте проект.
2. В **APIs & Services → OAuth consent screen** выберите **External**, заполните название и email поддержки. В **Test users** добавьте свой Gmail.
3. В **Credentials → Create credentials → OAuth client ID** выберите **Web application**.
4. Добавьте адреса:
   - **Authorized JavaScript origins:** `https://second-brain-production-e19a.up.railway.app`
   - **Authorized redirect URIs:** `https://second-brain-production-e19a.up.railway.app/api/auth/google/callback`
   - Для локальной проверки: `http://localhost:8787` и `http://localhost:8787/api/auth/google/callback`.
5. Скопируйте **Client ID** и **Client secret**.
6. Задайте переменные окружения:

```env
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_REDIRECT_URI=https://second-brain-production-e19a.up.railway.app/api/auth/google/callback
OWNER_EMAIL=your@gmail.com
```

7. Перезапустите приложение. На Railway переменные добавляются в **Variables** сервиса, после сохранения сервис перезапускается сам.

Пока приложение в режиме **Testing**, войти смогут только добавленные Test users. Для личного использования этого достаточно; чтобы пускать любой аккаунт владельца без ограничений, опубликуйте приложение (Publish app). Запрашиваемые scopes — только `openid`, `email`, `profile`, они не требуют дополнительной проверки Google.

Если `APP_PASSWORD` оставить заполненным, на экране входа появится резервный вход владельца по паролю. Если очистить — останутся Google и Telegram-вход, если они настроены.

### Вход и регистрация через Telegram-бота

Бот выдаёт логин и пароль, поэтому отдельная форма регистрации на сайте не нужна: аккаунт создаётся при первом сообщении боту.

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, придумайте имя и получите токен вида `123456789:AA...`.
2. Добавьте в переменные окружения:
   - `TELEGRAM_BOT_TOKEN` — токен из BotFather.
   - `PUBLIC_URL` — публичный HTTPS-адрес приложения. На Railway можно не задавать: используется выданный домен.
   - `APP_PASSWORD` — резервный пароль владельца и секрет для команды `/owner`.
3. Перезапустите сервер. При старте приложение вызывает `getMe`, сохраняет имя бота, регистрирует команды и устанавливает webhook на `<PUBLIC_URL>/api/telegram/webhook`. В логе появится строка `[telegram] Бот @... подключён`.
4. Откройте бота, нажмите **Start** или отправьте `/start`. Он пришлёт логин и пароль. Новый пользователь получает пустой кабинет; владелец — доступ к своим прежним записям.

Команды бота:

| Команда | Что делает |
| --- | --- |
| `/start` | Создаёт кабинет или выдаёт новый пароль существующему пользователю |
| `/password` | Сбрасывает пароль и присылает новый |
| `/id` | Показывает ваш Telegram ID |
| `/help` | Список команд |
| `/owner <APP_PASSWORD>` | Привязывает Telegram к кабинету владельца и выдаёт пароль owner |

Пароль имеет вид `XXXX-XXXX-XXXX`, хранится в виде scrypt-хеша и показывается только в чате с ботом. Отдельного экрана регистрации нет: на сайте нужно ввести логин и пароль, которые прислал бот.

**Привязка владельца.** Есть два способа:

- Узнайте свой ID командой `/id`, задайте `TELEGRAM_OWNER_ID=<id>` и перезапустите сервер. Этот Telegram-аккаунт автоматически получит кабинет `owner`.
- Или отправьте боту `/owner <APP_PASSWORD>` в личном чате.

Существующие записи уже принадлежат кабинету `owner`, поэтому после привязки они остаются на месте. Аккаунты, созданные другими людьми через бота, получают собственные пустые кабинеты и не видят данные владельца.

**Кто может регистрироваться.** По умолчанию — любой, кто знает имя бота. Чтобы закрыть доступ, задайте `TELEGRAM_ALLOWED_IDS` со списком ID через запятую или пробел. Свой ID можно узнать командой `/id`; владельца из `TELEGRAM_OWNER_ID` список не блокирует. Если бот должен быть только для вас, не публикуйте его имя и ограничьте список.

Webhook защищён заголовком `X-Telegram-Bot-Api-Secret-Token`; повторные апдейты Telegram отбрасываются по `update_id`. Если `PUBLIC_URL` не задан и приложение не на Railway, webhook не устанавливается — это нормально для локального запуска, но для работы бота в интернете нужен HTTPS-адрес.

### Напоминания: push и Telegram

Откройте **Настройки → Уведомления**. Здесь включаются push на каждом устройстве отдельно, сообщения в Telegram и расписание напоминаний.

- **За день до** — в 09:00 по выбранному часовому поясу. Включается для задач с датой и событий.
- **В момент времени** — когда наступает время задачи или начало события. Для задач без времени и событий «весь день» действует только напоминание за день.
- **Часовой пояс** — по нему считаются 09:00 и время задач. По умолчанию подставляется пояс браузера.

Push работает по HTTPS (на `localhost` тоже) в Chrome, Edge, Firefox, Safari и в установленном PWA. На iPhone нужна iOS 16.4+ и приложение, добавленное на экран «Домой». Telegram-напоминания доступны, если кабинет привязан к боту: владелец отправляет `/owner <APP_PASSWORD>`, остальные получают привязку при регистрации через `/start`. Кнопки «Проверить» отправляют тестовое уведомление.

Ключи VAPID для push генерируются автоматически при первом открытии настроек и хранятся в базе (`data/brain.db`) — они переживают перезапуск и деплой. Подписки устройств и настройки уведомлений у каждого пользователя свои. Повторные напоминания об одном и том же сроке не отправляются.

**Пока сервер спит, напоминания отправить нельзя.** Внутри процесса проверка идёт каждую минуту, а workflow `.github/workflows/reminders.yml` будит Railway по расписанию GitHub Actions (каждые 10 минут). Сервер принимает такой запрос только с подписанным OIDC-токеном GitHub и проверяет репозиторий, поэтому секрет в публичном репозитории не хранится. На Railway задайте:

```env
REMINDER_GITHUB_REPO=tenzidesingyt-cmd/second-brain
REMINDER_OIDC_AUDIENCE=second-brain-reminders
```

Необязательный `REMINDER_CRON_SECRET` включает простой запуск по заголовку `x-reminder-key` — удобно для ручной проверки или другого планировщика: `curl -X POST -H "x-reminder-key: <секрет>" https://<домен>/api/internal/reminders/run`.

Частые пробуждения не дают бесплатному сервису Railway засыпать и расходуют кредит. Если он ограничен, увеличьте интервал в `cron` workflow (например, до `*/20 * * * *`) или отключите workflow: напоминания продолжат приходить, пока приложение открыто или сервер бодрствует по другой причине.

### Доступ с телефона в домашней сети

1. Запустите сервер на компьютере.
2. Откройте на телефоне `http://<IP-компьютера>:8787` (IP печатается при старте сервера).
3. Установите приложение: в Chrome — «Установить приложение», в Safari — «Поделиться» → «На экран Домой».

Микрофон и установка PWA в интернете требуют HTTPS.

## Публикация в интернет

### Важно про GitHub Pages

GitHub Pages отдаёт только статические файлы. Этому приложению нужен Node-сервер, SQLite, загрузка файлов, WebSocket и прокси к OpenRouter, поэтому **GitHub Pages его не запустит**. Ссылка на репозиторий GitHub — это исходный код, а не работающий сайт.

Рабочая схема: репозиторий на GitHub + хостинг с Node и постоянным диском, подключённый к этому репозиторию. Ниже — готовые варианты.

### Вариант 1. Railway (бесплатный план)

Railway Free даёт кредит около $1 в месяц, 1 vCPU и 0,5 ГБ RAM на сервис, диск 500 МБ и бесплатный домен `*.up.railway.app`. Этого хватает личному кабинету. При простое приложение засыпает, а первый запрос после паузы запускает его заново — это занимает несколько секунд, данные на диске сохраняются.

1. Создайте проект **Deploy from GitHub repo** и выберите репозиторий.
2. Добавьте **Volume** и смонтируйте его в `/app/data`.
3. Задайте переменные:
   - `DATA_DIR=/app/data`
   - `APP_PASSWORD` — резервный пароль владельца
   - `OPENROUTER_API_KEY`
   - `TELEGRAM_BOT_TOKEN` — токен бота из BotFather
   - `TELEGRAM_OWNER_ID` — ваш Telegram ID (необязательно, для привязки владельца)
   - `TELEGRAM_ALLOWED_IDS` — список ID, кому разрешена регистрация (необязательно)
   - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, `OWNER_EMAIL` — после настройки Google OAuth
4. Сгенерируйте домен в **Settings → Networking → Generate Domain**.
5. Проверьте `https://<домен>/api/health`.

После деплоя откройте бота и отправьте `/start`; вебхук установится автоматически при старте сервиса. Railway засыпает после ~10 минут простоя, но входящее сообщение боту будит сервис, и ответ приходит после короткой паузы.

Dockerfile собирается автоматически. Не запускайте несколько реплик: SQLite рассчитан на один экземпляр. Dockerfile не должен содержать `VOLUME` — Railway отклоняет такой образ, диск подключается через настройки сервиса.

> Бесплатный лимит: если израсходовать $1 кредита, сервис остановится до следующего месяца. Для экономии включите **Serverless** в настройках сервиса — приложение будет спать после ~10 минут без запросов и не тратить кредит.

### Вариант 2. Render

В репозитории есть `render.yaml` и `Dockerfile`.

1. Загрузите проект в GitHub (см. раздел «GitHub» ниже).
2. В Render выберите **New → Blueprint** и подключите репозиторий.
3. Задайте переменные окружения.
4. Примените Blueprint.

Для SQLite и загрузок нужен постоянный диск, поэтому в `render.yaml` выбран платный план `starter` с диском 1 ГБ. На бесплатном плане диск недоступен: база и файлы будут пропадать при перезапуске.

### Вариант 3. Свой VPS

```bash
docker build -t second-brain .
docker run -d --name second-brain --restart unless-stopped \
  -p 127.0.0.1:8787:8787 \
  -v second-brain-data:/app/data \
  --env-file .env \
  second-brain
```

Поставьте перед контейнером Caddy или Nginx с HTTPS. Пример для Caddy:

```caddyfile
brain.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

Caddy сам получит сертификат и пробросит WebSocket. Порт наружу открывать не нужно.

### Временная ссылка без хостинга

Если нужно открыть приложение с телефона прямо сейчас, подойдёт туннель Cloudflare. Обязательно задайте `APP_PASSWORD`.

```bash
cloudflared tunnel --url http://localhost:8787
```

Команда выдаст HTTPS-ссылку вида `https://....trycloudflare.com`. Она работает, пока включены компьютер, сервер и туннель. После перезапуска адрес меняется. Для постоянного сайта используйте Render, Railway или VPS.

## Безопасность и резервные копии

- Для публичного доступа настройте Telegram-бота или Google, а `APP_PASSWORD` оставьте резервным входом владельца.
- Бот по умолчанию открыт всем, кто знает его имя. Закройте регистрацию списком `TELEGRAM_ALLOWED_IDS`, если кабинет только для своих.
- Данные пользователей изолированы на уровне SQL: запросы, файлы, поиск, WebSocket и ИИ работают в контексте текущего пользователя. Настройки ИИ и список аккаунтов доступны только владельцу.
- Никогда не коммитьте `.env` и `data/`: там ключи, личные записи и вложения. На хостинге храните секреты только в переменных окружения.
- Токен бота и ключи, попавшие в переписку или лог, перевыпустите: у BotFather — `/revoke`, в OpenRouter — удалить ключ и создать новый. После смены токена перезапустите сервер, чтобы обновился webhook.
- Резервная копия — это `data/brain.db` и каталог `data/uploads/`. Копируйте их при остановленном сервере или через `sqlite3 .backup`.
